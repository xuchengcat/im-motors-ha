# 智己汽车 Home Assistant 集成

当前仓库开发版为 **v0.8.0b2**，新增主账号官方行车日历与轨迹地图，并区分主账号和授权账号（副账号）的行程来源。使用步骤见下方[智己行程](#智己行程日历轨迹与地址)。开发版代码推送不代表已发布新的 HACS Release；安装前请核对版本，旧发行版可能尚未包含这些功能。

v0.7.2 将含义存疑的 `bmsPackSOH` 放在“其他”中，以英文原始字段保持启用。集成共提供 **173项默认启用的英文原始诊断字段**，统一添加“其他”标签，附中文暂定释义与确认状态，详见[字段说明](docs/other-fields.md)。**只读 / 全功能** 仅在首次配置时选择，配置完成后不可切换；旧配置固定为只读。全功能包含实验性车控，启用前须阅读风险提示。使用方式、支持范围与责任说明见[车控与风险说明](docs/vehicle-control.md)。

## 关于 bmsPackSOH：含义存疑，仅作 Other 原始字段展示

**目前不能确认 `period.bmsPackSOH` 是电池健康度，也不能确认其单位为百分比。此前将其命名为“电池健康度”并按百分比展示的解释已撤回。** 历史样本的94.0、93.9只是原始数字，不能据此认定为94%或93.9%的电池健康度。

该字段仅保留为 `Other / period.bmsPackSOH`，归于“其他”标签，**只读和全功能模式均默认启用**，不添加单位、百分比范围校验或统计类别。需要研究的用户，可在“设置 → 设备与服务 → 实体”搜索 `bmsPackSOH` 或按“其他”标签筛选查找。未返回、null或不支持的类型显示unknown，不能用它判断电池衰减或故障。

从早期版本升级时，原“电池健康度”实体保留ID、改为上述英文原始字段并清除百分比单位，不因移入“其他”而禁用；0.7.1由集成默认禁用的该实体会恢复启用，用户手动禁用的选择仍保留。

v0.6.2 支持 **HA 自行记录行程与轨迹详情**：按车辆启动至熄火分段，同日可记录多段；起终点单独使用连续稳定的停车定位确认，证据不足时显示待确认。过程样本保存位置与时间，详情提供地图轨迹和逐点时间表。记录复用原车况查询间隔，不额外增加云端查询频率；支持高德地址补全、日期筛选与导出。见[行程与轨迹说明](docs/trip-power-and-route.md)。

[![Validation](https://github.com/xuchengcat/im-motors-ha/actions/workflows/validate.yaml/badge.svg)](https://github.com/xuchengcat/im-motors-ha/actions/workflows/validate.yaml)

通过 Home Assistant 读取智己车辆电量、续航、总里程、胎压胎温、门窗、温度和充电信息，并管理账号认证会话。支持 HACS 自定义仓库安装，运行不依赖手机、ADB 或 Windows。

**v0.4.5 安装后只需在 HA 界面填写手机号和短信验证码，即可完成配置。** 通用协议参数随集成提供，账号加密密钥由每个 HA 实例在本地随机生成，无需手动准备 `production.imvault` 或挂载密钥。登录后自动读取关联车辆及已确认映射的车况，默认每60分钟查询一次，创建时可配置，最短5分钟。云端响应可能是缓存数据，只读查询也可能唤醒车辆。

## 通过 HACS 安装

要求 Home Assistant **2026.2 或更高版本**，已在 Linux HA 2026.2.3 验证。

1. 打开 HACS，点击右上角 **⋮ → 自定义存储库 / Custom repositories**。
2. 添加 `https://github.com/xuchengcat/im-motors-ha`，类型选择 **Integration / 集成**。
3. 搜索 **智己汽车**，下载最新版本，然后重启 Home Assistant。
4. 进入 **设置 → 设备与服务 → 添加集成 → 智己汽车 → 手机号与短信登录**，填写中国大陆手机号。
5. 提交发送短信，输入收到的验证码完成登录。

从 v0.1.0 / v0.2.0 / v0.3.0 升级时，在 HACS 更新并重启 HA，已有会话、外置密钥和实体可继续使用，不会自动迁移或重建。需要重新登录时，打开集成的 **重新配置 → 手机号与短信登录**；认证过期后的“重新认证”也提供同一入口。已有加密会话仍可通过导入方式配置。

这属于 HACS 自定义仓库安装，尚未申请默认仓库列表收录。可参考 [HACS 官方自定义仓库说明](https://www.hacs.dev/docs/faq/custom_repositories/)。

## 手动重新查询

设备提供“立即重新查询车况”按钮，可绑定仪表盘的 `button.press` 操作。点击后立即重新读取 v6 云端车况，跳过本地车况缓存并更新后续自动查询计时；云端仍可能返回车辆休眠前的快照。账号认证、VIN 校验和故障停止继续生效，临时 GET 网络错误或 HTTP 408/429/5xx 按退避计划恢复。

## 账号类型与实验性双登录

新增配置与“选项”中的账号类型由用户手动选择，不由手机号或服务端权限自动推断。旧配置默认按授权账号处理，保持原有行为。

- **主账号**：保留现有车况查询和运行模式；可开启官方历史行程查询，在日历中按日期同步日汇总、单次行程和轨迹地图。停用基于 HA 车况的本地采集，签到后续开发。
- **授权账号**：可在选项中启用现有本地行程记录。切换为主账号时不删除已保存的行程；在选项中切回授权账号后，可重新开启记录。

新发起的短信登录使用实验性 `clientType=WXAPP`，客户端类型加密保存在登录状态与会话中，令牌刷新及离线恢复沿用该类型。已有 `APP` 会话和升级前发出的短信流程仍沿用 `APP`；请通过“重新配置 → 手机号与短信登录”完成新登录以切换，不能直接修改旧令牌的客户端类型。其余 Android 请求头和签名暂保持现有协议，`WXAPP` 仅为登录/刷新字段的实验，不代表完整微信小程序实现。

已验证主账号 `WXAPP` 短信登录、只读查询及令牌刷新，并完成手机 App 保持登录时的短期共存验证。长期运行、手机重新登录后的行为及其他账号仍需继续观察。详见 [验证记录](docs/wxapp-validation.md)。

官方行车日历的接口、启用步骤、独立历史库和验证边界见 [主账号官方历史行程](docs/official-trip-history.md)。

## 智己行程：日历、轨迹与地址

此部分需要 **v0.8.0b2 或后续包含该功能的版本**。如果 HACS 最新发行版仍低于0.8，请等待对应版本发布，或将本仓库的 `custom_components/im_motors/` 目录安装到 HA 的 `/config/custom_components/im_motors/`，然后重启 HA。升级前请备份账号数据与密钥。

### 选择账号类型

打开 **设置 → 设备与服务 → 智己汽车 → 配置 / 选项**，选择账号类型并开启对应功能：

| 账号类型 | 启用开关 | 行程来源 |
|---|---|---|
| 主账号 | 查询官方历史行程（仅主账号） | 官方行车日历，可查询服务端仍保留的历史与轨迹 |
| 授权账号（副账号） | 根据 HA 车况自行记录行程 | 从开启后收到的车况、里程和位置自行记录未来行程 |

账号类型可在选项中修改，**不影响首次配置时固定的“只读 / 全功能”模式**。旧配置默认按授权账号处理。主账号不采集本地轨迹，授权账号不调用官方车主日历接口；选择“主账号”不会改变服务端的真实车主权限。当前官方日历仅支持关联一辆车的账号，签到尚未实现。

### 主账号：查看官方历史与轨迹

1. 将账号类型设为 **主账号**，开启 **查询官方历史行程（仅主账号）** 并保存。
2. 使用 HA 管理员账号打开侧边栏 **智己行程**（路径 `/im-motors-trips`），在“账号与车辆”中选择对应主账号。页面同时存在主、副账号时，请先确认选中了主账号。
3. 首次点击 **同步所选日期（最多31天）**，读取所选日期并加载官方日历。蓝色日期标记表示服务端返回该日有行程。
4. 切换月份、点击日历日期，即可同步该日；也可填写开始和结束日期后点击同步。每次最多31天，结束日期不能晚于今天。
5. 在 **每日汇总** 查看官方日里程、时长和行程数，在 **所选范围的行程** 查看各段起止时间、里程和起终点。
6. 点击 **查看详情与轨迹** 打开地图。默认只画完整轨迹线和起终点，不显示中间点标识；勾选 **显示轨迹点** 可查看中间点，点击下方表格序号可定位该点。

**“查询本地历史”只读取已同步的本机档案，不会请求新的官方行程。** 页面自动刷新也只查询本地档案；需要获取最新数据时点击同步。主账号不会自动扫描全部历史。单点时间若未由接口提供，会显示“接口未提供”，不根据行程时长补造时间。

### 授权账号：自行记录未来行程

将账号类型设为 **授权账号**，开启 **根据 HA 车况自行记录行程** 并保存。之后复用既有车况查询，在启动至熄火期间记录行程；可在“智己行程”选择该账号，查询已记录的日期，或点击 **立即采样车况**。

本地记录无法补回开启前的官方历史；起止时间和轨迹完整度受查询间隔、云端快照更新及停车定位证据影响。记录细节见[本地行程与轨迹说明](docs/trip-power-and-route.md)。

### 高德 Key：仅用于补全文字地址

**两种账号都不需要高德 Key 来绘制地图或轨迹。** 地图使用 HA 自带组件，底图需要网络加载；起终点坐标和轨迹点由智己数据提供，并在本地转换为地图使用的坐标。

如果接口没有返回起终点的文字地址，可按下面步骤补全：

1. 在对应账号的 **配置 / 选项** 中填写高德 **Web服务 API Key** 并保存。请使用支持逆地理编码的 Web服务 Key，并检查其配额与 IP 限制。
2. 回到“智己行程”并刷新页面，选择该账号，点击 **补全历史地址**。主账号后续同步行程时也会尝试补全缺失地址。
3. 没有 Key 时仍可查看坐标与路线；补全失败时保留原有坐标和行程，页面会提示错误。

Key 按账号分别加密保存，**副账号已配置的 Key 不会自动共享到主账号**；可在主账号选项中复用同一个 Key。输入框留空会保留已保存值，勾选“清除已保存的高德 Key”才会删除。补全地址不修改官方轨迹点，也不改变地图的绘制方式。

### 保存、备份与导出

主账号官方历史保存到账号数据目录的 `cloud-trips.sqlite3`，副账号本地记录保存到 `trips.sqlite3`；两者独立，切换账号类型不会合并或删除另一来源的历史。请备份完整账号数据目录及匹配的加密密钥；通过导入会话配置的账号应备份其自选目录和外置密钥。

页面支持按日期导出 JSON / CSV。日期列表导出包含行程摘要，完整轨迹点按需在详情中读取。主账号官方档案不接受手工导入；授权账号的本地档案仍支持既有历史导入功能。

接口、字段与验证边界见[主账号官方历史行程说明](docs/official-trip-history.md)。

## 当前能力

| 数据或功能 | 当前开发版行为 |
|---|---|
| 手机号与短信登录 | 仅需手机号和验证码；自动生成本地密钥、设备身份和加密会话，支持重发和重新认证 |
| 账号类型与双登录 | 手动区分主账号 / 授权账号；新短信登录实验性使用 WXAPP，旧会话需重新登录切换 |
| 官方行车日历 | 主账号按日期同步官方汇总、各段行程与轨迹；每次最多31天 |
| 本地行程记录 | 授权账号复用 HA 车况自行记录未来行程，独立于官方历史 |
| 轨迹地图与地址 | 地图和轨迹无需高德 Key；Key 仅用于可选的起终点文字地址补全 |
| 账号关联车辆 | 读取场景车辆列表，以 VIN 哈希建立 HA 设备 |
| 设备名称 | 统一显示为“智己汽车” |
| 账号凭据到期时间、建议刷新时间 | 显示服务器认证时间；到建议时间才刷新 |
| 元数据更新时间 | 本机读取时间，不是车辆上报时间 |
| 车型项目代码、场景支持标志 | 仅按实际响应显示；缺失或 null 显示 unknown，false 保持 false |
| 电量 / 续航 | 原始 SOC 百分比、CLTC 与估算续航分别显示 |
| 总里程 | `period.vehOdo` 直接显示为 km，按本车仪表盘读数核对；提供累计里程统计 |
| 胎压 / 胎温 | 四轮独立 bar / °C；胎压保留两位缩放精度 |
| 温度 | 车内、车辆外温、天气温度与左右空调设定分别显示 |
| 门窗 / 车锁 | 四门、舱盖、尾门、充电口盖、四窗开度及已核对的 App 云端锁闭显示 |
| 在线 / 连接 / 运行分类 | 独立在线与连接值；组合字段区分就绪、驻车、行驶 |
| 充电 | 17 种状态、目标电量、预约起止；当前剩余时间/耗时/功率按充电状态过滤 |
| 车辆位置 | 复用车况经纬度，观测格式码0/1按App高德调用链解释为GCJ-02并转换为WGS-84；未知坐标格式不展示 |
| 车型 / 数据时间 | 首页系列和项目代码独立于场景字段；提供云端根更新时间和读取时间 |
| 原始诊断 / 其他 | 173项英文原始字段均默认启用；bmsPackSOH仅作含义存疑的Other原始字段，按需查找。原值无单位，释义及确认状态见[字段说明](docs/other-fields.md) |
| chargedPower 单位 | 尚未确认；不发布为 kWh |
| 车况解析状态 | 已取得本车 v6 响应时显示“已接入”，具体缺失字段仍为 unknown |
| 请求失败或中断 | 临时 GET 故障持久退避重试；认证、数据校验与未知写请求结果仍停止 |

元数据接口可能不返回车型项目代码和场景支持标志。实体存在不代表已取得读数。功能标志也不代表当前车辆状态；完整说明见 [数据对应关系](docs/data-mapping.md)。

本集成使用短信登录、账号 token 刷新、场景关联车辆列表和 v6 车辆首页接口；主账号显式同步时还会读取官方日历与单次行程详情。每辆车按配置间隔查询，默认60分钟、最短5分钟，常规实体更新和重启不能绕过缓存；“立即重新查询车况”按钮可立即重新读取云端；默认只读模式不发送车辆控制指令；全功能模式按用户操作发送已核实格式的车控指令，详见[车控与风险说明](docs/vehicle-control.md)。不接入主动刷新接口或独立即时位置查询。旧版 11 个占位实体保留为禁用状态，新读数位于新增实体；启用占位不会产生数据。需要停止读取时，在 HA 禁用集成。服务端要求图形/风控验证或账号绑定时，登录流程停止并提示，当前 HA 界面暂不支持这些额外步骤。

单车账号的车况响应缺少 VIN 或 VIN 为 null 时，按本次请求的关联车辆接收数据；请求和缓存仍使用账号车辆列表中的 VIN。明确返回不匹配的 VIN，或多车账号缺少响应 VIN 时，仍暂停查询。

## 总里程

设备提供默认启用的“总里程”传感器，使用云端 `period.vehOdo` 整数公里原值，不添加偏移、不从续航推算。单位已与本车 LS6 的车辆仪表盘读数对照，其他车型仍需实车验证。自动查询和手动按钮都会更新里程；车辆休眠时可能显示旧快照。

累计统计使用 `state_class=total`，不设置重置时间；无效、缺失或负数读数显示 unknown，不填零。历史无单位里程诊断与旧占位实体保留原有身份，新增总里程实体单独记录公里历史。

## 车辆定位

设备新增“车辆位置” `device_tracker`，可直接放入 HA 地图卡片；坐标随每次车况查询更新，“立即重新查询车况”也会同步更新位置。来源是云端车况快照，车辆休眠时可能显示上次上报位置；根更新时间不是已验证的 GPS 采样时间。

当前支持本车观测到的 `coOdntSysFmt=0` 与 `1`，根据 App 3.2.4 直接调用高德 autonavi 逆地理编码的链路，按 GCJ-02 转换为 WGS-84。该链路不按格式码分支，0/1按同一高德坐标来源处理；该解释不是完整厂商坐标枚举；缺失、无效和未知格式会使定位实体 unavailable，其他车况继续显示。

新账号的私人数据和本地密钥自动保存在 HA 配置目录的 `.storage/im_motors/`；备份时保留整个目录。公开的通用协议参数不能解密这些账号文件。HACS 更新只更新代码，不替换账号密钥和数据。不要同时让多个进程或多份过时会话刷新同一账号。反馈问题时请使用 HA 脱敏诊断，不附带会话、密钥、手机号、VIN 或完整服务端响应。

## 开发

```sh
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-test.txt
python -m pytest -q
python tools/package_release.py
```

测试使用合成账号、临时加密文件和 mock HTTP，并阻止真实 HTTPS 连接。覆盖真实 HA 加载/卸载、配置流程、实体、诊断，以及缓存、轮换、故障停止和离线恢复。GitHub Actions 同时运行测试和 HACS 仓库检查。

本次映射依据 LS6 的授权云端响应、APK 展示逻辑及手机页面对照；各分组独立采样时间缺失，不能将根更新时间视为每个传感器的采样时间。长期运行、其他车型和不同 HA 环境仍需进一步验证。本项目为非官方集成，与车辆厂商没有关联。代码许可见 [LICENSE](LICENSE)。

车况更新间隔可在创建时的短信登录或会话导入页面设置，单位为分钟，默认60，必须为不少于5的整数。已有集成未配置此项时使用60分钟；可在重新配置的路径页面修改，重新认证保留原设置。账号认证仍每分钟本地检查，元数据仍缓存30分钟，两者不使用车况间隔。
