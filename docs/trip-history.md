# HA 自行记录行程

**0.6.0 更新：**已改为按车辆启动至熄火分段，0.6.1起复用原车况查询间隔，提供带时间的轨迹详情和地图。当前行为见[启动/熄火行程与轨迹详情](trip-power-and-route.md)。下文稳定停车规则是0.5.1版本的历史说明，不再用于新快照的分段。

在“设置 → 设备与服务 → 智己汽车 → 配置”启用“根据 HA 车况自行记录行程”。
保持现有智己账号，沿用车辆首页 v6 的运行状态、总里程和位置，不查询车主专用驾驶日历，不要求手机调试或重新登录车主账号。

侧边栏“智己行程”提供日期查询、每日里程合计、起终点时间与地址、进行中的行程状态，以及 JSON/CSV 导出。页面每15秒查询本地档案；只有手动“立即采样车况”才会额外查询一次现有车况接口。

## 记录方式与精度

- 起终点按持续稳定的停车定位确认：至少两个不同云端时间的有效定位，在50米内保持至少10分钟，且总里程未增加。
- 已确认的停车点会长期保留，作为下次出发地点；驶离100米并有行驶、里程增加或连续异地定位证据后开始记录。里程已增加也会开始记录，避免定位缓存阻挡出发识别。
- 到达新位置后先显示“确认停车中”，连续稳定后才结束；到达时间回溯至首次停稳样本，距离也取该样本读数，等待确认不算行驶时长。临时P挡和一次定位跳变不会直接结束行程。
- 若状态一直显示行驶，使用更保守的至少3个稳定样本、20分钟条件；里程缺失且没有驻车状态辅助时，也使用此条件。长时间拥堵等持续静止仍可能被误判，页面保留采样边界和确认信息供核对。
- 出发地点使用已确认停车点的固定坐标，时间与里程基线使用最后一次有效停车样本；显示的开始时间是首次观测到离开的云端时间。没有先前稳定停车样本时，起点继续标记不完整，不补造位置。
- 距离为终点与基线的 `period.vehOdo` 差值，原始分辨率是整数公里。读数缺失、回退时保留未知，不填零或构造距离。
- 若两个稳定停车位置之间仅发现里程增加或位移，却没采到行驶状态，保存为“推定区间”，可能包含多次短途；时长是两次采样的时间跨度。
- 重复、倒序、缺少云端时间、超前超过5分钟或过旧的快照不会生成新行程。过旧阈值为 `max(3 × 查询间隔, 15分钟)`。
- 长时间采样缺口、状态缺失、启用时已在行驶会标明不完整。进行中的行程与上一有效样本持久化，重启后继续。
- 云端根更新时间并不保证各字段、特别是 GPS 在该时刻独立采样；即使根时间较新，各分组仍可能来自缓存。
- 重复缓存不能作为第二个停车证据；定位不更新但里程持续增加时不能确认停车。定位缺失时保持进行中，等待定位恢复。定位始终没有随里程变化的行程会单独标记位置需要核对。
- 每日里程是已记录行程之和。跨天行程归于出发日；不会冒充官方日历的每日统计，也不会恢复启用前的两个月数据。

配置页可调整现有车况查询间隔，最低5分钟。较短间隔有助于减少漏采，但服务端缓存、车辆休眠和请求失败仍会影响结果。自动采样与手动采样共用原有缓存、认证和故障停止机制，没有新增高频定位或车辆控制接口。

## 高德地址

在集成配置页填写高德 **Web服务 API Key**，留空保留已保存的 Key，勾选清除可删除。
Key 加密保存到账号目录的 `trip-settings.imvault`，HA 配置条目只保存是否已配置，不将 Key 发给浏览器查询接口、诊断或实体。

地址使用高德逆地理编码，坐标顺序为经度、纬度，200米范围，并保留完整地址与最近 POI。
本集成已支持的 App 坐标格式0/1按现有高德链路处理，不把 WGS-84 直接当成高德坐标。
参见[高德官方逆地理编码文档](https://developer.amap.com/api/webservice/guide/api/georegeo/)。

不填 Key 时仍保存时间、里程和坐标；配置后点击“补全历史地址”。坐标查询结果永久缓存，已补全的历史查询不会重复消耗额度。高德失败不丢弃行程，页面显示错误以便手动恢复。

## 数据库与备份

每个现有账号目录下的 `trips.sqlite3` 包含：

| 表 | 用途 |
|---|---|
| `samples` | 采用的云端时间、接收时间、运行分类、总里程与坐标 |
| `trips` | 已结束行程/推定区间及采样不确定性 |
| `days` | 按出发日汇总的本地行程 |
| `metadata` | 正在进行的行程、上一有效样本和地址任务状态 |
| `geocache` | 已查询坐标的地址缓存 |
| `trip_revisions` | 停车定位规则升级、历史重算前的行程、日汇总和记录状态 |

不随 Home Assistant Recorder 保留期删除，不执行自动历史清理。SQLite 文件0600、账号目录0700；其中包含私人出行数据。备份 HA 的整个 `.storage/im_motors/`，包括数据库、账号目录和匹配的 `vault.key`。在线备份数据库应使用 SQLite backup 接口，或卸载本集成后复制完整账号目录。

从0.5.0升级时，按已保存原始样本一次性回放新停车规则；原记录先归档到 `trip_revisions`。没有样本覆盖的导入历史保留，不重新推测。后续重启不会反复重算。

## 查询和可选导入

界面查询只读本地数据库。管理员还可调用 `im_motors.query_trip_history`、`im_motors.import_trip_history`、`im_motors.sync_trip_history`。
`sync_trip_history` 默认立即采样现有车况，`geocode_only: true` 只补全地址。服务查询和导入需要 `entry_id` 与车辆哈希 `vehicle_id`，可从已认证的 `im_motors/trips/entries` WebSocket 命令取得。

支持导入页面导出的 JSON/CSV，或使用下列合成示例整理历史数据；导入不会要求智己车主登录。每次最多2MB、366天、10000段行程，整个文件验证后事务合并，重复ID不会产生重复记录。

```json
{
  "days": [{"date": "2026-10-18", "distance_km": 12.3}],
  "trips": [{
    "date": "2026-10-18",
    "start_time": "2026-10-18 23:40:00",
    "end_time": "2026-10-19 00:20:00",
    "distance_km": 12.3,
    "duration_minutes": 40,
    "start_address": "示例起点",
    "end_address": "示例终点"
  }]
}
```

CSV 包含 `date,daily_distance_km,daily_duration_minutes,start_time,end_time,distance_km,duration_minutes,start_address,end_address`。
同一天可多行，但日汇总列必须一致；只有日汇总、无行程的行可留空起止时间。不从不完整行程列表推算官方日里程。

## 手机比对

先保存配置并确认侧边栏显示有效采样时间。完成一次正常驾驶并驻车后，等待下次车况采样，核对开始/结束地点、总里程差和采样边界。
首次验证需要真实驾驶周期；离线测试、旧云端快照或手动制造状态不能证明实车准确性。
