# 启动/熄火行程与轨迹详情（0.6.2）

启用本地行程记录后，每次明确观测到车辆启动，开始一段行程；首次明确观测到熄火时立即保存。一天可有多段，启动但未移动的周期也保留。P 挡、原地等候或临时停车不会结束仍然启动的车辆行程。状态缺失时等待明确的熄火证据，不能把 unknown 当成熄火。

从0.6.2起，时间分段和起终点定位分开处理，恢复稳定停车约束：至少两个不同云端时间的有效位置，在50米内稳定至少10分钟，累计里程不增加；缺少里程与停车状态辅助时至少3个点、20分钟。重复缓存、单次GPS跳变、仍启动的原地P挡，不构成熄火后的停车确认。

起点使用出发前已确认的稳定停车点，不使用已经开出去后的第一条行驶坐标。熄火后先保存行程，终点标为“待确认”，后续稳定停车证据到来时更新同一段行程的位置，行程起止时间和数量保持不变。确认时间与位置样本时间独立保存，不当作熄火时间。下一次启动或未知状态下里程再次变化时，结束上一段的确认窗口，不能把再下一段的停车点借给上一段。移动证据出现时，过期的停车起点会失效。

GPS一直停留在旧起点、但累计里程增加时，不把重复的旧位置确认成终点。证据不足时位置留空、地址不查询；列表与详情显示“待确认”。地图的“起/终”标记只来自已确认稳定停车位置；蓝线仍保留过程中的原始有效采样，首末原始点不再冒充已确认起终点。

启动依据 `powerTrain.eptReadyStatus` 的 1/0。这里指车辆 READY 电源状态，电动车无需燃油发动机实际转动。开始和结束为云端快照中的观测时间，并保留相邻采样的时间边界；不是精确的物理操作时间。里程采用累计里程差，回退或缺失时不补造。

0.6.1起，行程记录严格复用原有车况查询，遵循配置的车况查询间隔，不另设高频采样，也不绕过缓存。每60秒的协调器检查只负责原有更新流程，不代表每60秒获取一次云端车况。只有用户点击“立即采样车况”或原有重新查询按钮时，才会手动绕过缓存。认证、请求锁和故障停止规则保持生效。0.6.0曾默认强制每60秒请求，现已撤销。

每个采用的云端快照保存时间、接收时间、启动状态、运行分类、累计里程及可用经纬度。重复/倒序和过旧快照继续跳过，云端未更新时无法获得更密的真实定位点。

在行程列表点击“查看详情与轨迹”，通过已认证的 `im_motors/trips/detail` WebSocket 命令查询本地过程样本。详情包含逐点时间表；点击序号定位，点击“查看整段轨迹”恢复全图。使用 HA 自带地图及底图接口，无需额外地图 JS Key。高德 Web 服务 Key 仍仅在服务器端补全地址。

地图使用 WGS-84，保存的 App GCJ-02 点按已有转换逻辑显示。缺失坐标或超过15分钟的间隔分段显示，不用起终点规划结果冒充实际行驶轨迹。原始云端根时间尚未证明为 GPS 独立采样时间。历史记录没有采样点时，详情明确提示无法恢复过程；不补造过去的道路。

首次升级按已保留的样本重算，旧的 ready/driving/parking 分类可还原当时有明确证据的启动状态；无法分类的样本仍为未知。原行程、日汇总和记录状态先存入 `trip_revisions`，导入历史和没有采样覆盖的记录保留。重启不反复重算。私人数据库需按原文档备份。
