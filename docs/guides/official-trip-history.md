# 主账号官方行车日历

本功能对应 App 爱车首页右上角日历入口，每日归档日期、日汇总、当天行程与单次轨迹，展示只读本地数据库；仅查询，不修改 App 的行程采集或轨迹权限。随机自动签到是独立选项，见[每日签到](daily-checkin.md)。

## 使用与每日归档

1. 在集成选项中将账号类型设为“主账号”，开启“每日自动归档官方行程（仅主账号）”。
2. 首次启用后检查近60天；后续每天凌晨3点（HA时区）运行一次，当天尚未执行时启动补跑。中断任务可续传。
3. 打开侧边栏“智己行程”，选择主账号。日历蓝色标记只代表本地已有行程的日期，点击日期、查询列表及打开轨迹均不发起官方请求；未归档日期等待自动任务或手动补同步。
4. 需要主动补查时选择起止日期，点击“手动补同步（最多31天）”；不能选择未来日期。`im_motors.sync_trip_history` 服务仍支持 `start_date` / `end_date`，默认今天，`geocode_only` 仅补全地址。

自动任务以本机数据库中的行程ID和列表字段判断是否缺失或变化，不重复下载完整、未变化的详情。每日执行记录、上次成功日期及失败状态保存到数据库；当天普通失败不会自动反复重试，下一日再检查。未完成的日期不覆盖旧归档。认证、协议与车辆范围错误停止任务；单日数据不完整时保留该日原数据，并继续归档其他日期。

当前仅支持账号关联一辆车。账号类型是本地选择，服务端仍验证真实车主权限；不能将授权账号改选为主账号来获得车主权限。

## 协议证据与通讯

静态证据来自 App 3.2.4 的 `DriveDataViewModel`、`DrivingDataListActivity`、`TripDataService`、`TripDataDetailBean`、`DriveDataMapActivity` 与 `ImJsCommonImpl2.getApiSignature`；同时核对官方生产 H5 页面及 `05cbf71` 静态资源。另核对[官方 Android 下载入口](https://m-dl.immotors.com/)所指向的3.2.7样本，其通用 H5 参数与旧样本一致。APK、恢复代码和个人响应保留在工程外的本地研究/加密目录，不随集成发布。

| 用途 | 主机 | GET 路径 | 参数 |
|---|---|---|---|
| 日历及每日汇总 | m.immotors.com | `/app/planet/api/v1/drive/daily/new` | `tripDate=YYYY-MM-DD` |
| 当天行程分页 | m.immotors.com | `/app/planet/api/v1/drive/daily/trips` | `tripDate`、`offset`、`limit=5` |
| 单次行程详情 | mh.immotors.com | `/app/vus/v3/drive/daily/trip/detail` | `tripId`、`tripStartTime`、`tripEndTime` |

`offset` 是从1开始的页码，不是条目偏移量。校验 `totalCount`、重复ID、分页是否完整，以及返回VIN是否与关联车辆一致；分页不全或任一详情失败时，不覆盖该日已归档数据。

H5 使用 `android-h5` 和独立通用签名参数，对完整URL、排序后的签名头和实际查询串签名；请求包含 WebView 的 User-Agent、Origin、Referer 和 X-Requested-With 上下文。实测缺失上下文的请求返回22064，补齐后的请求被接受；未将某一个头单独认定为唯一必要条件。原生详情沿用现有 Android 原生签名。两条链路共用当前账号的 Bearer 会话及账号锁，不需要再次登录手机。

H5 成功响应的外层可为 `resultCode=success` 且数据加密，解密后校验内层 `resultCode=200`。23373（非车主）、22061（认证失败）、22064（协议校验失败）分别提示，不转换为“无行程”，不自动循环重试。

## 数据与地图

- 远程 `hasTripDates` 规范化为日期用于归档发现；页面日历标记从本地已归档行程生成。
- 日里程使用服务端 `dayMileage`，不以单次里程之和替代；日时长使用 `dailyMileageDuration`。
- 列表使用 `tripId`、完整 `tripStartTime` / `tripEndTime`、`tripMileage`、`tripDuration`。跨天日期保留；无时区的详情查询时间按 Asia/Shanghai 转为 Unix 毫秒，与 App 深链语义一致。
- 详情使用 `tripStartLat/Lon`、`tripEndLat/Lon` 和 `poiList` 的经纬度。依据 App 将这些坐标直接传给高德的实现，地图按 GCJ-02 转为 WGS-84。
- 轨迹按服务端顺序保存并连接；无效点保留为断点。真实样本的 `poiList` 没有单点时间，保持未知，不按起止时间插值。原始速度值不额外换算。
- 地图详情使用 HA 的地图组件。针对该组件默认时间提示会假设点含时间的行为，对无时间点显示固定提示；数据中不补造时间。
- 服务端没有地址时保留坐标；可使用原有加密保存的高德 Web服务 Key 补全地址，并标注高德来源。没有Key也能看坐标和轨迹；已验证使用有效 Web服务 Key 补全起终点地址。

官方数据单独保存在账号目录 `cloud-trips.sqlite3`（0600权限）；副账号本地采集仍使用 `trips.sqlite3`。切换账号类型不会合并、覆盖或删除另一来源的历史。主账号不会写入本地车况采样表。轨迹点按需从详情读取，不随日期列表的15秒本地轮询反复传输。官方档案不接受手工导入，避免将手工数据标成官方来源。

历史库含个人位置，应随账号数据一起备份。官方后续移除的行程保留在本地并标记来源已不存在；远程返回空结果不会清零已保存的官方日汇总，失去某日权限不会清空既有归档。已有轨迹和坐标不会被缺失值覆盖，相同坐标的地址也会保留。本地归档不按60天删除，日历会保留这些日期。

## 验证与限制

已验证主账号 WXAPP 会话的官方日历查询、单日完整同步、真实轨迹及起终点读取、HA 正式页面的地图底图和线路显示，以及高德文字地址补全。桌面和390px手机布局均已检查。

Python / HA 回归覆盖配置流程、账号角色、车辆范围、分页完整性、错误与无行程的区别、独立归档和地图详情数据。正式HA地图引擎还验证了主账号默认隐藏中间点时，创建与更新两条路径均保留全部线段；勾选“显示轨迹点”可恢复中间点标识。副账号显示方式不变。

长期接口稳定性、其他车型、多车账号和其他地区尚未验证；可查询范围由服务端和App中既有权限决定。若此前没有采集轨迹，集成不能恢复厂商没有保存的数据。
